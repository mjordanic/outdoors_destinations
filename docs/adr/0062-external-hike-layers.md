# External hike layers, starting with Ireland

Some countries have few OSM hiking relations but publish official trail registers as open data. Ireland's Sport Ireland trail register lists 1,029 walking trails under CC BY 4.0, and 72 % of their starts have no Trailhead within 1 km. Such registers can fill the thinnest countries, as long as their licences stay apart from the ODbL data. The big commercial platforms (AllTrails, Komoot, Wikiloc, Strava, Outdooractive) forbid reuse in their terms; the sources register (ADR-0060) records why each one is rejected.

**An external hike is its own record, beside the OSM ones.** An *external source* has a register id, a `fetch` step that caches its data as GeoJSON under `data/external/<source>/` (`dayhike fetch-external --source <id>`), and an adapter that reads the cached file into hikes. Each hike has a name (or none: see **Name** below), a line from its start, a stable record id and the record's page. `dayhike ingest --external <id>` adds each one as a DayHike of kind `external`, with `source` the register id, `source_ref` the record id and `source_url` its page. Ingest refuses a source the register does not list as `used`. An external hike never edits, merges into or borrows the geometry of an OSM hike. Its line is the source's own, with no OSM ways, so its GeometryStore rows are vertices only.

- **Licence model.** Under the OSMF's Collective Database guideline, an external layer that is kept as its own rows, each with its own geometry, is a separate database next to the OpenStreetMap one, and it keeps its own licence. The page credits each one from the register: the hike panel names the source and its licence and links the record; `credits.html`, `/api/info` (`attribution`) and the export's `meta.json` (`sources`) carry a credit per source; a GPX of an external hike credits the source, not OpenStreetMap. What HikesAlike computes for every hike (amenities near the start from OpenStreetMap, heights, land cover, climate) is computed for an external hike too, and those values keep the licences of their own sources.
- **Id.** A hash of `(source, source_ref)`, mapped into [2^39, 2^40): above every OSM relation id, below every built id (ADR-0038), and a JavaScript-safe integer. A rebuild from a newer copy of the source gives the same id to the same record, so a `#hike=` link survives.
- **Twin rule.** An external hike that is a Twin of a relation DayHike (the Twin rule of `similarity`) is dropped, and so is one that is a Twin of an external hike kept before it, so the same walk is not listed twice; the ingest report counts the two apart. When an official hike and an OSM hike are the same walk, the OSM hike is listed: it is ODbL data and it can be edited on the map. Only relation DayHikes that start near the external hikes, and whose length allows a Twin, are compared.
- **Floor.** The 1 km floor of ADR-0033 applies; there is no upper cap.
- **Name.** An external hike is labelled as an OSM relation is (ADR-0017): the record's own name (Sport Ireland `Name`, Lipas `name`, Turrutebasen `rutenavn`, `Ukjent` counting as none); else "Hike near {place}", the nearest OSM place (city, town, village or hamlet) within 5 km of its start; else the source's last fallback: for Turrutebasen the maintainer and the route number (the bare number with no maintainer). A Sport Ireland or Lipas record with none of these is synthetic, as an unnamed OSM relation is: NameOrigin `synthetic` and the label "Unnamed hike ({source} {source_ref})" with the source's short name ("Unnamed hike (Lipas 123)", "Unnamed hike (Sport Ireland trail/5)"), so the page never shows a raw `{source}:{source_ref}`; its DayStages are named from that label. An adapter gives a record with no name of its own `name` None and its `fallback`; ingest picks the label. Ireland and Finland used to leave such a record out; they now keep it. Every other external label has NameOrigin `external`.
- **DayStages.** A kept external hike longer than 25 km is cut into DayStages by the rules, thresholds and code of ADR-0040 (`dayhike.stages.split`, the same huts, places and parking from the OpenStreetMap snapshot; stage names "{hike}, stage k: {from} – {to}" from the hike's label; a stretch with no cut point for more than 25 km gets no stage). The hike stays listed beside its stages. A stage walks the source's line in its direction: external hikes have no height rule, so a stage is never reversed. A stage is an external hike of its own: kind `external`, NameOrigin `stage`, the licence and credit of its source. Its `source_ref` and `source_url` are its route's, as a relation DayStage's is its tour's (`relation/{tour}`), and its id is a hash of `(source, source_ref, start and end of the stage as latitude,longitude to 6 decimals)`, in the external range: the walk, as a relation DayStage's id is a hash of its Route, so a stage keeps its id when other stages, other records or the numbering k change.
- **Twin rule for stages.** Per stage, as for a relation DayStage (ADR-0040): the route itself is compared as before and a route that is a Twin of a relation DayHike is dropped, with no stages cut from it. A stage is dropped as a Twin of a relation DayHike or of a built DayStage near it (the OSM hike is listed), or of an external hike or stage kept before it (an external route, then the stages in order). The ingest report counts these in `dropped_external_twin` and `dropped_external_duplicate`, and counts the stages that were kept in `external_stages` (also part of `external_added`).
- **Unchanged downstream.** Sampling (DEM, WorldCover, CHELSA), similarity, Twins, Ranking, search and the serving export read an external hike as any other DayHike. Checked in code: the facts that read OSM way tags (SurfaceMix, TarmacApproach) are missing (NaN) for a hike with no ways, not zero, and its difficulty is missing (a source's own grading is not SAC). The page offers no "Edit on the map" for it: `/api/hikes/{id}` gives `built` as null, and its head links no OSM relation.

**First source: Sport Ireland Trail Routes** (`ie-sport-ireland`). The ArcGIS layer `GetIrelandActiveTrailRoutes`, fetched in WGS84 and filtered to `Activity = 'Walking'`. `TrailID` is the record id (`trail/{TrailID}`), `Website` its page, `Name` its name. The record's `Latitude`/`Longitude` is its start, so the line is turned to start at the end nearer it. A multi-part line keeps its longest part, joined to every part whose end lies within 50 m (the gap a main walk joins, ADR-0012); parts farther away are left out, as the TrailGraph would not walk the jump (ADR-0009).

**Second source: Lipas** (`fi-lipas`). The REST API `https://api.lipas.fi/v2/sports-sites`, one GeoJSON geometry collection on each record, 100 records a page. Types 4405 (hiking route) and 4404 (nature trail) with `status` active. `lipas-id` is the record id, `name` its name, and the page is `https://www.lipas.fi/liikuntapaikka/{id}`. `dayhike fetch-external --source fi` is this register id. Parts whose ends lie within 50 m join into one walk as Sport Ireland's do (the longest part, extended at its ends), and `source_ref` is the Lipas id. A part that does not join, whether apart from the walk or a branch off it, is a separate piece of the same name, as is the walk itself then: `source_ref` is `{id}/{n}`, numbered from 1 by each piece's start (latitude, then longitude), so a side path Lipas drew apart from the main walk is kept and documented instead of dropped. Nature trails use the same 1 km floor as hiking routes. A 2–3 km floor for them was considered, because many are short, and rejected: a walk of 1–3 km is still a DayHike under the floor above, and dropping it in the adapter would not count it as too short. The production licence is CC BY 4.0 (the dev API spec's CC BY-SA is not the production term). Credit as that page asks: "Jyväskylän yliopisto, Lipas Liikuntapaikat.fi", which is the register name.

**Third source: Turrutebasen** (`no-turrutebasen`). The national Geonorge GPX in WGS84. `dayhike fetch-external --source no` is this register id. A `Fotrute` route element is one segment: its name is the route number (`rutenummer`), its description the route name (`rutenavn`), its source the maintainer. Ski, bike and other types are left out. Segments of one maintainer and route number join as Lipas parts do; a blank maintainer is a group of its own. `source_ref` is the route number; a part that does not join, a branch included, is `{rutenummer}/{n}`, numbered from 1 by start (latitude, then longitude). When more than one maintainer uses a route number, their groups are not pieces of one route: a maintainer's group is `{maintainer}/{rutenummer}` (and `{maintainer}/{rutenummer}/{n}`), a blank maintainer's keeps the bare number. Each piece's own name is its own segments' most common `rutenavn`, and `Ukjent` counts as none; with none, ingest names it after the nearest place (**Name** above), and only with no place within 5 km its most common maintainer and the route number, else the route number. Ties go to the alphabetical name. There is no per-route page. The 1 km floor and the DayStages of a long route apply at ingest. Credit Kartverket, CC BY 4.0.

**Fourth source family: France** (`fr-*`, #129). One adapter, `read_schema_randonnee`, reads the GeoJSON of any dataset that follows the [schema_randonnee](https://github.com/PnX-SI/schema_randonnee) (Geotrek exports do). Each dataset is its own register id, so its licence and credit are its own: `data/fr_randonnee.toml` lists every dataset examined (id, data.gouv.fr page, file, the licence code data.gouv.fr publishes), `dayhike fetch-external --source fr` caches each one that passes two gates and says why it skips the others, and `--source fr-ecrins-randonnees` caches one. *Licence gate:* the published licence must be Licence Ouverte 2.0 (`lov2`) or the ODbL (`odc-odbl`, which the project already offers); the dataset is not downloaded otherwise. *Schema gate:* every record carries `id_local`, `nom_itineraire` and `pratique`, and `id_local` is distinct and filled, since it is the `source_ref`. A record is a walk when `pratique` is "A pied" or "pédestre"; mountaineering, mountain-bike and trail routes are left out. The name is `nom_itineraire`, the page the record's `url`, the line its geometry without heights, parts that meet joined as for Sport Ireland. `id_osm` is not read: a Twin of an OSM relation is dropped by the Twin rule, as for every source. The cache keeps only those fields, so the records' images (all rights reserved) are never copied. Examined: the Écrins (Licence Ouverte 2.0, 189 of 205 records are walks) is used. The Dordogne's PDIPR loops (`lov2`) fail the schema gate (their fields are `NOM_BOUCLE` and `TYPE_ITIN`, no record id), Vandœuvre-lès-Nancy (ODbL) too (`id_local` is 0 throughout, urban art walks), and the Cévennes and the Pas-de-Calais are published under the first Licence Ouverte (`fr-lo`), which the licence gate does not take; adding `fr-lo` to `FR_LICENCES` would admit the Cévennes (1162 records, but `id_local` repeats 510 ids, so its file needs the schema gate relaxed too). The other 127 "randonnée" datasets and the PDIPR ones do not declare the schema and are not read. FFRandonnée's GR and PR data is proprietary and out.

**Fifth source: South Tyrol hiking trails** (`it-odh-suedtirol`). Issue #130 asked for the NOI Open Data Hub tourism API's CC0 hikes with GPX tracks, filtered by `LicenseInfo.License`. In the live API (17 Nov 2026) no hike is both: the 3,012 CC0 hiking records (`lts`) carry only start points, and the ones with a `GpsTrack` (4,589 `civis.geoserver`, 1,049 Trentino, 4 ArcGIS) are `Closed`; the only CC0 records with tracks are ski slopes. The `civis.geoserver` records are the Autonomous Province of Bolzano's own trail layer, and the province's open data portal (`data.civis.bz.it`, dataset `percorsi-escursionistici`) lists it as cc-zero. So the adapter reads that WFS layer (`Routes-HikingTrails`, GeoJSON in WGS84, 200 features a request, 4,609 segments, four decimals) and keeps the register id of issue #130. The portal states a licence per dataset and none per record, so the gate is the dataset's: `fetch-external` reads `license_id` from the portal first and refuses anything but `cc-zero`, fetching nothing. A feature has `ID`, `CODE` (trail number, repeated across the province), `NAME` (often missing; `.` is a blank) and a line. Segments of one `CODE` and `NAME` join as Lipas parts do; a segment with neither is a walk of its own, so anonymous trails meeting at a junction are not chained; `source_ref` is the lowest segment `ID` of the walk (the segment's own `ID` when it is one segment), and `{ID}/{n}` for pieces of one segment that do not join. A piece's name is its `NAME`, else ingest names it after the nearest place, else "Trail {CODE}"; with neither it is synthetic. The page is the dataset's. It is a marked-trail network, not a tourism board's list of classic outings, so many walks are unnamed numbered trails (3,511 of 4,593 pieces). The 1 km floor (3,710 pieces reach it) and the DayStages of a long trail apply at ingest. CC0 asks for no credit; the province is named as a courtesy. The Open Data Hub marks the same trails `Closed`, so the province's own licence statement is the one this source relies on.

**Consequences.** The Catalog `dayhikes` and the export `hikes` gain a nullable `source_url`; a Catalog or export from before reads it as none. The export format stays 5. The ingest report counts `external_added`, `external_stages` (of them DayStages), `dropped_external_twin` (Twins of relation DayHikes and built DayStages), `dropped_external_duplicate` (Twins of an external hike kept before) and `dropped_external_length`. Without `--external` the Catalog is the same as before, row for row. With it, long routes add DayStages and unnamed routes change name: the catalog the Europe rebuild makes differs from one built before this change. Finland (Lipas cache of 2026-11-16, Finnish OSM extract of that day, 1,719 routes kept): 51 routes are over 25 km, 38 of them give 72 DayStages of 8.5–24.7 km (median 15.7 km); no route changed name, as that cache holds no record without a name (the fetch used to leave them out). In the Turrutebasen cache 7,643 of 36,358 segments have no `rutenavn`: those routes get a place name instead of the maintainer and number. Finland (#127), Norway (#128) and South Tyrol (#130) are each one more adapter in `EXTERNAL_SOURCES` and one more register row turned `used`.

**Considered Options**

- **Merge an official hike into the OSM hike it matches.** Rejected: the row would mix ODbL and CC BY data, which is what the Collective Database guideline keeps apart.
- **List the official hike, not the OSM one, when both are the same walk.** Rejected: the OSM hike is the one a visitor can edit on the map and that other OSM-built hikes refer to.
- **List both.** Rejected: Ranking would show the same walk twice. Twins in a Ranking are already grouped, but search and the map would still show two hikes on one line.
- **Snap the official line onto OSM ways.** Rejected: the hike would then be made from OSM geometry, which is a different licence and a different walk from the one the source publishes.
